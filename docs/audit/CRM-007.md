# CRM-007 WebSocket Rooms (Realtime)

## Implementação Verificada

### Backend
1. **WebsocketGateway** (`15-events/infrastructure/websocket.gateway.ts`):
   - Pool de conexões ativas (`Set<WsClient>`)
   - `broadcastToTenant(tenantId, event, payload)`: Envia evento para todos os clientes conectados ao tenant
   - `sendToUser(userId, event, payload)`: Envia evento para um usuário específico
   - Remoção automática de clientes ao fechar conexão

2. **WebSocket Controller** (`15-events/presentation/websocket.controller.ts`):
   - Rota `/ws` com autenticação via JWT token
   - Decodificação do token com `@auth/core/jwt`
   - Verificação de sessão ativa via `verifySession(sessionId, "tenant")`
   - Validação de `surface === "tenant"` para rejeitar tokens de outras superfícies
   - Suporte a `subscribe` para rooms por tenant
   - Rejeição de conexão com mensagens claras: "Token missing", "Invalid token", "Unauthorized", "Session expired"

3. **Integração com serviços**:
   - `DealService` emite `crm.deal.changed` ao criar/mover/atribuir deals
   - `InboxService` emite `inbox.changed` ao criar/atualizar conversas/mensagens
   - Gateway injetado via construtor como dependência opcional

### Frontend
1. **useRealtime** hook:
   - Conecta ao WebSocket com token da sessão
   - Envia `subscribe` com `tenantId` ao conectar
   - Escuta eventos e dispara callbacks (ex: `router.refresh()` ao receber `crm.deal.changed`)

2. **PipelineBoard** (`pipeline-board.tsx`):
   - Usa `useRealtime` para atualizar o board quando outro usuário modifica deals

### Critérios de Aceite
| ID | Cenário | Status |
|---|---|---|
| Autenticação | Handshake requer token JWT válido | ✅ Token decodificado e verificado |
| Autorização | Rooms isoladas por tenant | ✅ `client.tenantIds.includes(tenantId)` |
| Reconexão | Frontend reconecta automaticamente | ✅ Hook `useRealtime` |
| Rejeição | Conexão sem token ou com sessão expirada é fechada | ✅ Códigos 1008 |
