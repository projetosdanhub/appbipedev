# CRM-006 Atribuição a setor/cargo/membro

## Implementação Verificada

### Backend
1. **DealService** (`deal.service.ts`):
   - `assign(context, dealId, expectedVersion, departmentId, routingRoleId, assignedMembershipId)`: Atribui deal a setor/cargo/membro com verificação de versão otimista
   - `claim(context, dealId, expectedVersion)`: Membro assume deal para si
   - `release(context, dealId, expectedVersion)`: Membro libera deal

2. **InboxService** (`inbox.service.ts`):
   - `assign(tenantId, conversationId, expectedVersion, departmentId, routingRoleId, assignedMembershipId, actorMembershipId)`
   - `claim` e `release` para conversas

3. **DealRepository** (`deal.repository.ts`):
   - `assign()` com transação, SELECT FOR UPDATE, assignment_histories e outbox_events

4. **ConversationRepository** (`conversation.repository.ts`):
   - `update()` com assignment_histories e outbox_events quando assignment muda

5. **Controllers**:
   - `PUT /api/v1/tenants/:tenantId/deals/:dealId/assignment`
   - `POST /api/v1/tenants/:tenantId/deals/:dealId/assignment/claim`
   - `POST /api/v1/tenants/:tenantId/deals/:dealId/assignment/release`
   - Endpoints equivalentes para conversations no inbox.controller.ts
   - `GET /api/v1/tenants/:tenantId/deals/:dealId/assignment-candidates` com integração ao `TeamService.getAssignmentCandidates`

6. **Contratos** (`packages/contracts/src/index.ts`):
   - `assignmentTargetSchema` com `departmentId`, `routingRoleId`, `assignedMembershipId` e `expectedVersion`
   - `claimResourceBodySchema` com `expectedVersion`
   - Permissões: `crm.deals.assign`, `crm.deals.claim`, `crm.contacts.assign`, `crm.contacts.claim`, `inbox.conversations.assign`, `inbox.conversations.claim`

### Frontend
- DealCard com seletor de responsável (`memberships` dropdown)
- InboxClient com opções de claim/assign
- Atualização otimista com rollback em caso de conflito

### Testes
- `CRM-006 Assignment Concurrency: should fail assignment with ConflictError if expectedVersion mismatches` ✅
- Concurrency test via `deal.service.test.ts`: `should prevent concurrent updates on the same deal using version checking` ✅
