# Auditoria de Execução: CRM-002 (Tags e Segmentos)

## Checklist de Conclusão

- [x] O Prisma Schema contempla os modelos `Tag`, `ContactTag` e `Segment` com chaves de tenant e índices otimizados para busca.
- [x] A camada de API implementa CRUD completo em `TagService` e `SegmentService` com validação no `TagEntity` e `SegmentEntity`.
- [x] Regras de negócio de `Tags` (cores em token, prevenção de duplicidade, vínculo via ContactTag) homologadas por testes unitários (`tag.service.test.ts`).
- [x] Regras de negócio de `Segments` suportam montagem de Abstract Syntax Tree (AST) para gerar dinamicamente a query SQL (`compileAst` validado em `segment.service.test.ts`).
- [x] A permissão apropriada (ex: `crm.tags.manage`, `crm.segments.read`) é avaliada antes da execução dos comandos no domínio, não dependendo de rotas inseguras.
- [x] Integração no Frontend concluída via `TagManagerModal` e `SegmentBuilderModal` que comunicam via Next.js Server Actions.

## Observações

- A árvore de filtros no segmento é traduzida para fragmentos de SQL parametrizado, conferindo escalabilidade sem comprometer segurança, pois os campos e valores são passados de forma higienizada ou parametrizada no banco.
- O mapeamento de Custom Fields na AST está traduzindo propriedades com o prefixo `custom_` para acessos via JSONB (`->>`).

**Status Final:** Aprovado e concluído.
